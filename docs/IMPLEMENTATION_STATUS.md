# 구현 상태

2026-11-06 기준. 이 프로젝트는 자체 가상환경과 데이터로 단독 실행되며 다른 프로젝트에 의존하지 않는다.

## 현재 동작

공공정책 문서를 PDF, TXT, 붙여넣기로 받아 이해관계자 2~3명을 추출하고, 역할별 독립 입장, 쟁점 정리, 쟁점 토론을 거쳐 내 입장의 주의 조항과 역할별 의견서를 만든다. 5페이지에서 단일 프롬프트 결과와 비교 평가할 수 있다.

- **파이프라인:** 단계 순서는 서버가 고정한다. 단계별 JSON 스키마, 원문 인용 검증, 참조 ID 검증, 오류를 돌려주는 수정 재호출 1회를 적용한다.
- **서버 자료:** 역할 에이전트와 최종 정리는 첫 호출에서 검색이 강제되고 토론은 선택이다. 역할 추출과 쟁점 정리는 쓰지 않는다. 라운드는 3회로 제한하고 상한에 닿으면 도구 없이 답을 받는다. 서버 자료의 인용도 원문과 대조하며, 실행 당시 출처를 결과에 함께 저장한다.
- **검색:** 키워드 검색이다. 공백이 깨진 PDF 글자, 긴 낱말의 앞부분(국토교통부와 국토부), 최근 1년 자료를 반영한다. 입력 문서와 내용이 같은 자료는 제외한다.
- **평가:** `evaluate`는 문서 발행일 이전의 정책 자료만 보고 실행한다. `score`는 키워드로 대략 비교한다.
- **기록:** 실행별 입력, 모델, 프롬프트, 호출별 시간과 토큰, 오류, 검색 기록을 저장한다.
- **복구:** 시간 초과는 서버가 한 번 다시 보낸다. 그래도 실패하면 저장된 단계에서 사용자가 재시작한다.

## 데이터

서버 자료 67건(정책 34, 의견 33)을 적재했다. 평가 문서는 6건이고 정답 초안은 3건, 쟁점 12개다. 내용과 한계는 [데이터 계획](DATA_PLAN.md) 9절에 있다.

## 평가 결과

정답 초안의 쟁점 중 결과가 언급한 수의 평균이다. 조건마다 3회 실행했고 단일 프롬프트는 6회다. 사람 채점이 아니라 키워드 비교이며 정답도 확정 전이다. 평가에서는 공고 뒤 자료와 의견 자료를 숨기므로 서비스에서의 서버 자료 효과를 재지 않는다. 프롬프트 수정 전 21회는 `data/reviewed/runs-before-prompt-fix/`에 보관했고 그때 합계는 문서만 6.67, 서버 자료 7.67, 단일 프롬프트 9.67이었다.

| 문서 | 쟁점 | 문서만 | 서버 자료 | 단일 프롬프트 |
|---|---:|---:|---:|---:|
| 서울 청년월세 | 5 | 2.67 | 2.67 | 3.83 |
| 서울 청년수당 | 5 | 2.67 | 2.67 | 3.50 |
| 희망두배 청년통장 | 2 | 1.33 | 1.33 | 1.83 |
| 합계 | 12 | 6.67 | 6.67 | 9.17 |

- **단일 프롬프트가 이 기준에서 가장 높다.** 단일 프롬프트는 긴 목록을 나열하고 PolicyLens는 주의 조항 3~6개를 제시한다. 이 점수는 넓게 나열할수록 유리하고 초점, 판단의 질, 인용 정확도는 재지 못한다. 그래도 PolicyLens가 실제 쟁점을 더 많이 찾는다는 근거는 없다.
- **서버 자료의 효과는 이 평가에서 보이지 않는다.** 합계가 같고 실행별 값도 겹친다.
- **5페이지 글이 줄었고 항목 수도 줄었다.** 정답 문서 기준 글자 수 중앙값은 서버 자료 3,612자에서 2,862자로 21%, 문서만 3,681자에서 2,460자로 33% 줄었다. 주의 조항이 4개 이하인 실행이 4회에서 10회로 늘어, 줄어든 양의 일부는 항목 수에서 왔다. 점수 변화와의 인과는 확인하지 않았다.
- **역할은 안정됐다.** 21회 모두 3명이고 모두 집행기관을 포함한다. 서울 청년월세는 6회 중 5회가 1인 가구와 특수유형으로, 서울 청년수당은 6회 중 5회가 미취업과 단기근로로 나뉘었다. 희망두배 청년통장은 일부가 여전히 선정·제외로 나뉜다. 문서에 없는 implied 역할은 63개 중 0개다.
- **비용은 서버 자료 조건이 크다.** 정답 문서의 토큰 중앙값은 서버 자료 19.6만, 문서만 14.1만이다. 호출은 서버 자료 14~17회, 문서만 10~11회다(단일 프롬프트 1회 포함).
- **자료를 쓰는 비율이 낮다.** 서버 자료 조건 12회에서 실행당 검색은 4~8회, 인용은 0~4건이고 5회는 인용이 없다. 토론 에이전트는 한 번도 검색하지 않았다.
- **평가 규칙을 지키지 못했다.** [데이터 계획](DATA_PLAN.md)은 프롬프트를 고칠 때 본 문서를 최종 평가에서 빼라고 한다. 실제로는 평가 문서 결과를 보고 검색과 프롬프트를 고친 뒤 같은 문서로 평가했다. 수치가 유리하게 나왔을 수 있다.

서비스 모드에서는 평가에 없는 자료까지 쓴다. 서울 청년월세 공고로 웹 흐름을 진행했을 때 역할 에이전트가 서울시와 국토부 중복 선정자의 지급중지 공지를 찾아 환수 위험이 실제로 발생했다고 썼고, 국회예산정책처 결산 분석과 서울시 입장 자료를 인용했다. 다만 1회 실행의 사례이고 결과가 나아졌는지는 측정하지 않았다.

## 실제 시험에서 발견해 고친 결함

- 모델이 문서에 인쇄된 쪽 번호를 인용해 긴 TXT의 역할 추출이 실패했다. 인용문이 있는 쪽으로 서버가 맞춘다.
- 도구를 선택 사항으로 두면 역할 에이전트가 쓰지 않았다. 첫 호출에서 강제한다.
- 병렬 도구 호출을 나눠 보내 HTTP 400이 났다. 호출들을 한 메시지로 합친다.
- 인용 오류 메시지가 어느 인용인지 말해주지 않아 수정 재호출이 실패했다. 쪽과 앞부분을 넣었다.
- 검색이 국토교통부로 찾으면 국토부라고 쓴 공지를 놓쳤고 옛 공고가 최신 공지를 밀어냈다. 긴 낱말의 앞부분과 최근 자료 가산을 넣었다.
- 공고의 가운뎃점과 물결표 변형, 보이지 않는 문자 때문에 같은 문장이 인용 검증에서 거부될 수 있었다. 비교 전에 지운다. 실패한 실행의 전체 인용을 확보하지 못해 원인은 추정이다.
- 엔드포인트가 간헐적으로 요청 하나를 멈췄다. 같은 요청을 다시 보내면 15초 안에 끝났다. 시간 초과를 90초로 두고 한 번 다시 보낸다.
- 대학 AI 윤리 가이드라인의 반각 가운뎃점(U+FF65) 때문에 맞는 인용이 거부되어 토론이 멈췄다. 비교 전에 지우는 문자에 넣었다.

최종 평가 21회에서 전체 실행을 다시 돌린 경우는 인용 문구가 바뀐 1건이다. 별도로 평가 도중 네트워크가 끊겨 12회를 다시 돌렸다. 가운뎃점 수정은 평가 뒤에 했고, 인용을 더 넓게 받는 변경이어서 평가를 다시 돌리지 않았다.

## 검증

Django 테스트 65개 통과, 마이그레이션 0006 적용, 시스템 검사 통과. 프로젝트 전용 `.venv`에서 실행했다. 최종 코드로 실제 모델을 써서 서울 청년월세 공고의 웹 흐름을 끝까지 진행했다. 호출 12회 중 1회가 멈췄다가 자동 재시도로 복구되었고, HTTP 오류와 브라우저 콘솔 오류는 없었다. 5페이지 근거, 찾아본 기록, 의견서, 비교 화면을 확인했고 390px에서 가로 넘침이 없다. Chat Completions 호환 엔드포인트(gpt-5.6-luna)로만 시험했고 Responses 모드의 도구 호출은 모의 시험뿐이다.

대학 AI 활용 윤리 가이드라인(37쪽 PDF)을 사용자 요청으로 지정 엔드포인트에 보내 학습자 입장으로 시험했다. 이 문서는 서버 자료에 넣지 않았다. 최종 코드의 웹 흐름은 호출 15회(비교 포함), 36만 토큰에 시간 초과와 HTTP·브라우저 오류가 없었고 인용 수정 재호출이 1회 있었다. 서버 자료 인용은 없었다. 문서가 자율 가이드라는 성격은 프롬프트 수정 뒤 전체 실행 3회 모두 언급됐지만 2회만 별도 주의 조항이었다. 과제 입력 금지 조항은 3회 모두 별도 주의 조항으로 나오지 않았다.

5페이지 글 양을 항목별 목표 글자 수로 줄였다. 같은 앞 단계 결과로 최종 정리만 다시 돌린 결과 주의 조항 글자 수가 위 가이드라인 2회에서 21%, 25%, 서울 청년월세 2회에서 16%, 29% 줄었고 수정 재호출은 없었다. 모바일 5페이지 높이는 5,479px에서 5,070px로 7% 줄었다. 비교 화면은 두 결과를 같은 높이의 상자에 넣고 단일 프롬프트 쪽 마크다운 기호를 지워 데스크톱 높이가 6,423px에서 1,637px로 줄었다. 단일 프롬프트 답변의 내용은 비교 기준이므로 줄이지 않았다.

## 알려진 한계

- 인용 검증은 문구의 존재만 확인하고 주장을 뒷받침하는지는 판단하지 않는다. 역할의 red_line에서 문서에 없는 전제가 섞인 사례가 있었고 이를 잡는 장치는 없다.
- 평가는 실행한 세션 소유자만 할 수 있고, PolicyLens 과정을 본 뒤 평가하므로 맹검이 불완전하다. 사람 평가자의 비교는 아직 없다.
- 의견 자료의 대부분은 시의원 발언이다. 청년 본인의 공개 의견은 조사 보고서뿐이고, 시민단체 성명과 청원은 찾지 못했다.
- 검색은 전체 자료를 메모리에서 훑는다. 지금 규모에서 0.04초이고 자료가 크게 늘면 전문 검색으로 바꿔야 한다.
- 실행은 동기 호출이고 SQLite 트랜잭션 안에서 진행된다. 다중 사용자 운영에는 PostgreSQL, 워커, 동시 실행 제어가 필요하며 구현하지 않았다.
- 상황 메모와 쟁점 선택 입력은 2·3페이지 디자인 유지 지시에 따라 넣지 않았다.
- 같은 문서라도 역할을 나누는 기준과 주의 조항은 실행마다 달라질 수 있다.
- `docs/previews/`의 화면은 서버 자료 표시 이전이다.
- 턴제는 단계가 3명 기준 8개에서 20개가 되고, 서버 자료 검색 라운드를 포함한 모델 호출은 32~37회(이전 12회 중앙값 13.5회), 총 호출 시간 218~235초(이전 중앙값 147초), 토큰 약 51만~58만(이전 중앙값 약 19.9만)이다. 문서 전문을 매 호출에 보내므로 긴 문서에서 비용이 크다. 청년월세 공고 한국어·영어 실행 각 1회의 실측이며 표본이 작다.
- 의견 하나짜리 턴도 빠르지 않다. 독립 입장 턴은 중앙값 12~14초(최소 7초, 최대 30초)로, 턴마다 서버 자료 검색이 거의 한 번씩 들어가서 5~6초 추정에 못 미쳤다. 토론 턴은 중앙값 6~7초다. 3쪽 전체는 약 121~132초, 4쪽은 56~65초다(이전 중앙값 61초, 49초). 쟁점 정리는 한 번의 호출이라 화면이 말풍선을 3초 간격으로 나눠 보여준다.
- 이전 방식으로 만든 실행은 새 단계 계획과 맞지 않아 이어갈 수 없다. 앞 단계 번호와 종류가 달라 새 문서로 다시 시작해야 한다.
- 토론 대화 구조는 대학 AI 윤리 가이드라인 1건에서 토론 9턴을 실제 모델로 재생해 확인했다. 표본이 작다. 재생 중 프롬프트가 `target_ids` 필드를 뭉뚱그려 지시했을 때 모델이 `issue_id`를 재시도까지 빠뜨려 멈춘 적이 있어 필드 이름을 밝혔고, 그 뒤 9턴은 재시도 없이 끝났다. 멈추더라도 재시작 버튼으로 그 턴부터 이어진다.
- 글자 수는 프롬프트 지시일 뿐 서버가 막지 않는다. 길다고 검토를 멈추는 것이 더 나쁘다고 판단했다. 한자는 서버가 거부해 재시도하며, 문서 자체에 있는 한자와 인용은 허용한다.
- 텍스트를 붙여넣은 문서는 제목이 없어 "정책 검토"로 표시된다. 파일은 파일 이름을 쓴다.
- 쟁점 토론 도중에 멈춘 이전 실행을 이어가면 발언 순서가 새 계획과 어긋날 수 있다. 끝난 실행의 표시에는 영향이 없다.
- 영어 출력은 실제 모델로 1회 완주해 확인했다. 본문은 영어, 검색어는 한국어, 인용은 원문 그대로였다. 글자 수 지시는 지키지 않았다(독립 입장 reason 평균 527자로 목표 약 300자의 1.8배, 역할 이름 28~32자). 영어 실행은 20단계 중 2단계가 서버 자료 인용 검증에서 첫 시도에 실패해 재시도가 필요했고 한국어 실행은 0회였다. 표본이 1회씩이라 일반화할 수 없다.
- 언어는 업로드 때 한 번 정해지고 그 실행 동안 고정된다. 토글을 누르면 고른 파일은 사라진다. 기존 실행은 한국어다.
- 초기 시험에 쓴 대학 자료 4건(고려대, Dartmouth, 단국대, SUTD)은 외부 전송 승인을 기록하지 않고 지정 엔드포인트로 보냈다.

## 구현 이력

1. 독립 프로젝트, 문서 입력, 역할 추출, 단계별 검토, 자동 진행, 5페이지 화면을 만들었다. 수정안 생성과 수정본 재검토는 이후 제거했다.
2. 논쟁 지점 중심으로 재설계했다. 역할 2~3명 가변, 쟁점 유형 6개, 역할별 독립성, 주의 조항과 의견서.
3. 단일 프롬프트 비교 평가를 추가했다.
4. 실제 모델로 문서 5건을 완주하고 토론 구체성을 고쳤다. 토론은 쟁점별로 입장이 다른 상대 발언에 답한다. 반응 라벨은 수정 전후 거의 같았고 전월세 예시의 발언 내용은 구체화되었다.
5. 서버 자료, 도구, 에이전트 루프를 추가했다.
6. 전체 데이터를 수집하고 평가 명령과 호출 기록을 추가했다.
7. 첫 화면 오른쪽 위에 한국어/English 슬라이드 전환을 추가했다. 선택한 언어는 `ReviewRun.language`에 저장되고 1~5쪽 화면, 의견서, 비교, 에이전트 출력(`prompts/lang_en.md`, `baseline_en.md`)이 그 언어를 따른다. UI 문구는 Django gettext(`locale/en`)이고, 쟁점 유형·우선순위·입장·반응 값은 한국어로 저장하고 화면에서만 번역한다.
8. 입장 나누기와 쟁점 토론을 턴제로 바꿨다. 독립 입장과 토론이 모델 호출 한 번에 항목 하나씩, 역할이 차례로 돌아가며 올라온다(`TURNS = 3`: 역할당 의견·쟁점·토론 바퀴 최대 3). 독립 입장 턴은 자기 의견만 받고 역할의 첫 턴만 서버 자료 검색부터 한다. 더 낼 것이 없는 턴은 호출 없이 건너뛰고 화면에 말풍선을 만들지 않는다. 3명 기준 단계는 8개에서 20개(호출 최대 20회)가 되었다.
9. 쟁점 토론을 대화로 바꿨다. 쟁점마다 사용자가 고른 역할이 자기에게 불리한 점을 먼저 말하고, 다음 역할은 그 발언에, 셋째 역할은 그 발언과 앞선 답변에 답한다. 토론 턴이 앞선 토론 발언을 `history`로 받고, 서버가 답할 ID(`claim_id`, `reply_id`)를 배정해 빠뜨리면 재시도한다. 고른 역할은 에이전트에게 전달되지 않고 발언 순서만 정한다. 같은 문서의 재생에서 토론 `reason` 평균이 378자에서 128자로, 입장 나누기는 246자에서 85자로 줄었고 반응은 수용 편중(답변 6개 중 5개)에서 제한 6, 반박 3으로 바뀌었다. 말풍선은 글을 자르지 않고 전문을 보여주며, 1쪽 문서 이름 입력과 2쪽의 근거 펼침·역할 수정을 뺐다.
