# Phase 1 · 사용자 문서 입력과 A 조건 v1

입력할 대학과 문서는 사용자가 정한다. 개발용 입력기는 UTF-8 텍스트 파일을 받는다. PDF를 사용할 때는 사용자가 본문을 텍스트로 준비하고 사례에 원본 쪽수·출처를 기록한다. 모바일 업로드·PDF 자동 추출은 이후 화면 구현 범위다.

1. 사용자가 문서 제목·출처와 검토할 원문을 제공한다. 조항과 위치를 사용자가 선택한다.
2. 과제 상황·학습 목표·공통 질문은 연구용 가정으로 별도 입력한다. 문서가 달라지면 쟁점도 새로 정한다. 같은 연구 안에서 결과를 비교할 때는 확인된 문서 해시와 사례를 공유한다.
3. 아래 형식으로 사례를 저장하고 이 폴더에서 `python3 prepare_case.py 정책본문.txt 사례.json`을 실행한다. 출력 JSON은 선택한 원문과 A 설정 버전을 담는다. 파일 미지정·빈 본문·원문에 없는 인용은 거부한다.

**모의 입력 예시** · 글쓰기 수업의 AI 사용 범위를 다루는 가상 문서다. 예시를 사용할 때만 본문 파일에 다음 문장을 넣는다.

> 과제별 허용 도구와 사용 범위는 제출 전에 안내한다.

```json
{"title":"글쓰기 실습 지침","source":"개발용 모의 문서 v1","clauses":[{"location":"첫 문단","quote":"과제별 허용 도구와 사용 범위는 제출 전에 안내한다."}],"learning_goal":"논거의 배열을 평가한다.","situation":"교정은 허용한다고 안내했고 학생이 AI가 제시한 문단 순서도 반영했다.","question":"교정과 문단 재배열을 어떻게 구분해 사전에 안내할까?"}
```

[연구 설정](study_v1.json)에 작성일·버전·역할별 수용 조건·설문 원문을 고정했다. 첫 입장은 공통 프롬프트, 자기 역할 배경·지침, 단계 지침, 확인된 사례·조항 순으로 조립한다. 이후 단계의 공유 범위는 [토론 명세](../DEBATE_PROTOCOL.md)를 따른다. 역할 카드는 연구팀 작성본으로 시작한다. 승인된 합성 프로필을 채택할 때는 출처 ID를 연결하고 버전을 올린다.

B의 자료 수집·DB·실행은 보류한다. A 단독 경로는 두 번째 결과나 선호 투표를 요구하지 않는다. A의 1차 입장부터 최종 편집까지는 재시도 제외 11회이며 모델 연결은 Phase 4에서 진행한다.
